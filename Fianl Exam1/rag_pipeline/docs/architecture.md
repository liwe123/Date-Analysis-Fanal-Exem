# RAG Pipeline 架构设计文档

## 1. 执行摘要

本项目构建了一个企业级RAG（检索增强生成）系统，用于处理企业内部的非结构化文档（如技术文档、FAQ、产品手册等），提供语义搜索和智能问答能力。

**业务问题**：企业员工花费大量时间在杂乱的文档中寻找答案。本系统通过将文档转换为可搜索的向量索引，并结合大型语言模型，实现快速、准确的知识检索。

### 2.2 数据流

**索引流程**：
```
原始文档 → 文件扫描 → 文本提取 → 文本清洗 → 分块 → 嵌入生成 → ChromaDB存储
```

**查询流程**：
```
用户查询 → 查询解析 → 查询嵌入 → 向量检索 → 结果格式化 → LLM生成 → 返回答案
```

## 3. 技术选型

### 3.1 嵌入模型

**选择**：`all-MiniLM-L6-v2` (sentence-transformers)

**理由**：
- 免费，无需API Key
- 本地运行，无网络延迟
- 384维，存储和计算效率高
- 支持中英文

**备选方案**：
- OpenAI `text-embedding-ada-002`：质量更高，但需要API Key且收费
- `paraphrase-multilingual-MiniLM-L12-v2`：多语言支持更好，但更大

### 3.2 向量数据库

**选择**：ChromaDB

**理由**：
- 简单易用，无需额外服务
- 本地文件存储，无需Docker
- 内置嵌入函数支持
- 适合中小规模数据（10-10000文档）

**备选方案**：
- Milvus：更适合大规模数据，但需要Docker部署
- Qdrant：性能更好，但配置更复杂
- FAISS：Facebook开源，纯向量搜索，无元数据支持

### 3.3 分块策略

**选择**：递归字符分割 (RecursiveCharacterTextSplitter)

**理由**：
- 保持语义完整性
- 支持多种分隔符
- 可配置块大小和重叠

**参数**：
- `chunk_size = 500` 字符（约250个中文字）
- `chunk_overlap = 50` 字符（约25个中文字）

**分隔符优先级**：
1. `\n\n`（段落分隔）
2. `\n`（换行）
3. `。`（中文句号）
4. `.`（英文句号）
5. ` `（空格）

### 3.4 LLM（可选）

**选择**：OpenAI GPT-3.5-turbo

**理由**：
- 质量高，回答准确
- API调用简单
- 支持中文

**回退模式**：
- 当没有API Key时，直接展示检索到的文档内容
- 保证系统在无LLM情况下仍可使用

## 5. 接口设计

### 5.1 命令行接口

```bash
# 索引
python run.py index [--data-dir DIR] [--reset]

# 查询
python run.py query "问题"

# 交互式查询
python run.py interactive

# 统计信息
python run.py stats

# 重置数据库
python run.py reset
```

### 5.2 Python API

```python
# 索引流水线
pipeline = IndexingPipeline(db_path="./chroma_db")
result = pipeline.run("./data/documents")

# 查询流水线
query_pipeline = QueryPipeline(
    chroma_manager=pipeline.chroma,
    embedder=pipeline.embedder
)
result = query_pipeline.run("什么是Python？")
```

### 5.3 Streamlit界面

- 侧边栏：索引按钮、统计信息、设置
- 主区域：查询输入、结果展示、来源引用

## 6. 性能考虑

### 6.1 索引性能

- 批量嵌入生成：使用`batch_size=32`
- 持久化存储：避免重复索引
- 增量更新：支持添加新文档

### 6.2 查询性能

- HNSW索引：O(log n)复杂度
- 缓存机制：缓存嵌入向量
- 批量查询：支持批量检索

### 6.3 存储优化

- 向量量化：可选的向量压缩
- 元数据索引：加速过滤查询
- 分区存储：按类别分区
