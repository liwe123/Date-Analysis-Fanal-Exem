# 大模型 Token、配额与限流故障处理

## API 配额耗尽或余额不足

当接口返回 `insufficient_quota`、`quota exceeded`，或供应商控制台显示余额不足时：

1. 检查 API 供应商控制台中的余额、配额和账单状态。
2. 充值、申请更高配额，或更换仍有可用额度的 API Key。
3. 临时切换到备用模型或兼容服务，确保问答入口仍可使用。
4. 减少不必要的重复调用，缓存查询解析结果，并限制并发和最大输出长度。
5. 不要持续重试余额不足错误；只有恢复额度后重试才有意义。

## HTTP 429 频率限制

HTTP 429 通常表示请求过快，不等同于余额耗尽。应采用带随机抖动的指数退避，
例如等待 2 秒、4 秒、8 秒后重试，并降低并发数。达到最大重试次数后切换备用模型，
或向用户明确提示稍后再试。

## 上下文 Token 超限

当接口提示 `context length exceeded` 或上下文 Token 超限时：

1. 缩短系统提示词和用户输入，移除无关历史消息。
2. 降低检索 `top_k`，截断或摘要过长的参考文档。
3. 将长文档分块处理，再汇总各分块结果。
4. 必要时切换到支持更大上下文窗口的模型。

## 认证 Token 过期

`token expired` 或 `session expired` 属于认证凭据过期，不属于 API 配额耗尽。
应刷新认证 Token，检查权限范围后重新请求。
